# Dialect Card: PostgreSQL

Dialect id: `postgresql`

Executor/runtime:
- Executor: Docker `postgres:16-alpine` through `AgentToolbox`.
- Runtime version: detected at execution time and recorded in `ddl_execution.runtime_version`.
- Enabled extensions are not assumed unless the final DDL creates them.
- Treat this card as executor-grounded: generate for the configured Docker runtime and its default search path.

Core rules:
- Quote identifiers with double quotes only when the generated DDL already quotes identifiers.
- Prefer `GENERATED BY DEFAULT AS IDENTITY` for DB-managed integer surrogate keys.
- Use `BOOLEAN`, `TEXT`, `VARCHAR(n)`, `BIGINT`, `INTEGER`, `TIMESTAMP`, `DATE`, `TIME`, `NUMERIC(p,s)`, and `JSONB` where appropriate.
- PostgreSQL supports table-level `CHECK`, `UNIQUE`, `PRIMARY KEY`, and foreign keys.
- PostgreSQL supports partial indexes with `WHERE` and covering indexes with `INCLUDE`.
- `CREATE INDEX ... INCLUDE (...) WHERE ...` is valid when include columns and a predicate are both needed.
- Partial-index predicates must use only immutable expressions. Do not use rolling-time expressions such as `CURRENT_TIMESTAMP`, `CURRENT_DATE`, `LOCALTIME`, `LOCALTIMESTAMP`, `NOW()`, `clock_timestamp()`, `statement_timestamp()`, or `transaction_timestamp()`, including expressions such as `expires_at > (CURRENT_TIMESTAMP AT TIME ZONE 'UTC')`. Keep the current-time comparison in the query and emit a normal index on the timestamp column, optionally combined with a static partial predicate such as `status = 'active'`. If a physical plan requests an unsafe predicate, the compiler must omit or safely degrade that predicate and record a warning rather than copying it into DDL.
- `unaccent` is not available unless the final DDL includes `CREATE EXTENSION IF NOT EXISTS unaccent;`.
- Expression indexes using `unaccent()` require an immutable wrapper, for example `immutable_unaccent(text)` calling `public.unaccent($1)`. Do not make the wrapper call itself.
- Tests must not call `unaccent()` or `immutable_unaccent()` unless the final DDL actually defines the extension/function used by the test.
- Avoid MySQL-only syntax such as backticks, `AUTO_INCREMENT`, `UNSIGNED`, and inline `ON UPDATE CURRENT_TIMESTAMP`.
- Avoid SQL Server-only syntax such as square bracket quoting and `IDENTITY(1,1)`.

Review checklist:
- Identity syntax is PostgreSQL-native.
- JSON columns use `JSONB` unless a plain text fallback is intentional.
- Filtered/partial indexes use only immutable `WHERE` predicates; no current-time or other volatile/stable function appears in the predicate.
- Foreign keys are emitted after referenced tables exist or are inline only when valid.
- Any extension-dependent SQL has matching extension/function setup in the final DDL and in tests.
