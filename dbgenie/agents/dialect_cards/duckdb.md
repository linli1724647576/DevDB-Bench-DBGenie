# Dialect Card: DuckDB

Dialect id: `duckdb`

Executor/runtime:
- Executor: Python `duckdb` package through `AgentToolbox` in an in-memory database.
- Runtime version: DuckDB `1.5.4` via the Python `duckdb` package.
- The executor also detects the installed package version at execution time and records it in `ddl_execution.runtime_version`.
- Treat this card as executor-grounded: generate for the runtime used by the test executor, not for abstract or future DuckDB.

Core rules:
- DuckDB accepts double-quoted identifiers.
- Use `BOOLEAN`, `VARCHAR`, `TEXT`, `BIGINT`, `INTEGER`, `DOUBLE`, `DECIMAL(p,s)`, `TIMESTAMP`, `DATE`, `TIME`, `BLOB`, `UUID`, `JSON`, and array types where required by the SchemaIR.
- DuckDB 1.5.4 supports and enforces `PRIMARY KEY`, `UNIQUE`, `CHECK`, and basic `FOREIGN KEY` constraints. Preserve these constraints when they are declared in the SchemaIR.
- Do not use `GENERATED ALWAYS AS IDENTITY` or `GENERATED BY DEFAULT AS IDENTITY`; DuckDB 1.5.4 rejects identity constraints. When the SchemaIR explicitly requires a database-generated numeric key, lower it to a declared `CREATE SEQUENCE` plus `DEFAULT nextval('sequence_name')`.
- Basic inline and table-level foreign keys are supported, but do not emit `ON DELETE` or `ON UPDATE` referential actions; DuckDB 1.5.4 does not support `CASCADE`, `SET NULL`, or `SET DEFAULT` actions.
- DuckDB 1.5.4 supports `CREATE UNIQUE INDEX` for ordinary key columns. Emit it when it is explicitly declared by the SchemaIR or physical index plan.
- DuckDB does not use MySQL `AUTO_INCREMENT`, PostgreSQL identity syntax, or SQL Server `IDENTITY(1,1)` in this V1 pipeline.
- Avoid PostgreSQL-specific `JSONB`, partial index assumptions, and covering index `INCLUDE` unless a dedicated DuckDB tool verifies support.
- Vector search is executor-limited: `FLOAT[]` can store embeddings, but do not assume vector indexes or ANN syntax.

Review checklist:
- DDL avoids DBMS-specific syntax from MySQL, PostgreSQL, or SQL Server.
- Index syntax is conservative and simple.
- DDL preserves declared primary-key, unique, check, and basic foreign-key semantics.
- Constraint tests may verify basic `UNIQUE` and `FOREIGN KEY` enforcement, but must not require unsupported referential actions.
- Query-plan tests should not require index usage for tiny in-memory DuckDB datasets unless the plan has been verified.
