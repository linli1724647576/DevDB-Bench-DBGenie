# Dialect Card: SQL Server

Dialect id: `sqlserver`

Executor/runtime:
- Executor: Docker `mcr.microsoft.com/mssql/server:2022-latest` through `AgentToolbox`.
- Runtime version: detected at execution time with `SELECT @@VERSION` and recorded in `ddl_execution.runtime_version`.
- Tooling uses `mcr.microsoft.com/mssql-tools` `sqlcmd` to execute scripts against the SQL Server container.
- Treat this card as executor-grounded: generate for SQL Server 2022 container behavior and avoid features that require unavailable server configuration.

Core rules:
- Start generated SQL Server DDL with `SET QUOTED_IDENTIFIER ON;` and `SET ANSI_NULLS ON;`.
- Quote identifiers with square brackets when quoting is needed.
- Use `IDENTITY(1,1)` for DB-managed integer surrogate keys.
- Use `BIT`, `NVARCHAR(n)`, `NVARCHAR(MAX)`, `BIGINT`, `INT`, `DATETIME2`, `DATE`, `TIME`, and `DECIMAL(p,s)`.
- SQL Server supports table-level `PRIMARY KEY`, `UNIQUE`, `CHECK`, and foreign keys.
- SQL Server supports filtered indexes with `WHERE`.
- SQL Server supports covering indexes with `INCLUDE`.
- Avoid PostgreSQL-only syntax such as `GENERATED BY DEFAULT AS IDENTITY`, `JSONB`, and double quotes if the rest of the DDL uses bracket quoting.
- Avoid MySQL-only syntax such as backticks, `AUTO_INCREMENT`, and `UNSIGNED`.

Review checklist:
- Session preamble is present before filtered indexes or computed/indexed objects.
- Identity syntax is `IDENTITY(1,1)` and appears on an integer column.
- Filtered unique indexes are rendered as indexes, not table-level unique constraints.
- `INCLUDE` columns are not repeated in key columns.
- DDL order creates tables before `ALTER TABLE ... ADD CONSTRAINT` foreign keys.
