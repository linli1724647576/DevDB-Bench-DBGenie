# Dialect Card: MySQL

Dialect id: `mysql`

Executor/runtime:
- Executor: Docker `mysql:8.4` through `AgentToolbox`.
- Runtime version: detected at execution time with `SELECT VERSION()` and recorded in `ddl_execution.runtime_version`.
- Treat this card as executor-grounded: generate for the configured Docker runtime and default InnoDB behavior, not for arbitrary MySQL-compatible systems.

Core rules:
- Quote identifiers with backticks when quoting is needed.
- Use `AUTO_INCREMENT` for DB-managed integer surrogate keys.
- Use `BOOLEAN` as a tinyint-compatible logical type, `VARCHAR(n)`, `TEXT`, `BIGINT`, `INT`, `DATETIME`, `DATE`, `TIME`, `DECIMAL(p,s)`, and `JSON`.
- MySQL supports `PRIMARY KEY`, `UNIQUE`, indexes, and foreign keys on InnoDB tables.
- MySQL does not support PostgreSQL-style partial indexes with `WHERE`.
- MySQL does not support PostgreSQL/SQL Server covering index `INCLUDE`; include columns must be part of the key columns if truly needed.
- Avoid PostgreSQL-only syntax such as `GENERATED BY DEFAULT AS IDENTITY`, `JSONB`, and double-colon casts.
- Avoid SQL Server-only syntax such as square bracket quoting, `IDENTITY(1,1)`, and filtered index predicates.

Review checklist:
- Indexed text/blob columns are bounded or intentionally narrowed.
- Generated table, index, constraint, and foreign-key identifiers must not exceed 64 characters; shorten derived names deterministically while preserving uniqueness.
- InnoDB index keys must fit the 3072-byte limit. Account for up to 4 bytes per `utf8mb4` character across all indexed columns, and do not replace semantic uniqueness with a prefix-only unique index unless the requirement explicitly permits it.
- Create referenced tables before foreign keys that target them, or add foreign keys with `ALTER TABLE` after all participating tables exist.
- No `WHERE` clause appears in `CREATE INDEX`.
- No `INCLUDE` clause appears in `CREATE INDEX`.
- Foreign key column types are compatible with referenced key columns.
